# 脚本、章节与连续分镜（表B）

> 施工层（填表格式、布局坐标查表、动词→引擎 helper 映射、硬数字、?lint 门槛）见 `references/execution-contract.md` 索引；本文管叙事结构与逐句语义。

## 表B · 结构表与持续主体

先识别**最外层论证模式**定整段骨架，内层模式决定每一拍画什么：

| 文案特征 | 模式 | 骨架 |
|---|---|---|
| 第一第二第三 / 三个原因 | 列举 | 索引轨 ①②③，讲到哪项哪项亮 |
| A 比 B / 而 / 相比 | 对比 | 左右两栏（L2）、天平、双柱 |
| 因为所以 / 导致 | 因果 | 链条：触发 → 作用 → 结果 |
| 从…到… / 先…再… | 流程 | 管道漏斗（L4）、行走路径 |
| 但是 / 不过 | 转折 | 翻面、划掉、天平倾斜 |
| 能否 / 什么时候 | 设问 | 问号、闸门、时钟 |
| 数字百分比排名 | 数据 | 格子阵（L8）、计数、梯队 |
| 用户投资者员工 | 人的行为 | 人物（L7）加道具 |

**持续主体规则**：每段只选 1 个主体对象 + 至多 1 组人物；主体必须是观众叫得出名字的（「压力①」「数据中心」），禁用 P1/Block A 开发编号；主体写成**形态链**逐环对应话题（例：`压力块① → 落地 → 长成数据中心 → 被监管框罩住 → 归档回①号槽位`）；话题结束主体必须归档，不能凭空消失。

|---|---|
| 最外层模式 / 骨架 | |
| 持续主体及形态链 | |
| 人物组（角色） | |

**通过条件**：主体有观众看得懂的名字；形态链覆盖本段每个话题；首帧末帧都写清。

## 字幕显示

- 每屏最多 2 行，每行不超过 14 个汉字，英文按约半个汉字计。
- 优先在逗号、顿号、空格和语义边界断行，不拆专有名词。
- 每条高亮 1–3 个主体、数字、结论词或专有名词；颜色读本期 token，不写死青色。
- 字幕入场约 0.18 秒，上移 20px 并淡入；结束即消失，避免与下一条叠字。
- 画面文字仍是关键词和必要标注，不能复制整句形成双层字幕。

## 章节与画面语言

- 每个视觉机制段承载一个论点或关系，通常 5–25 秒；边界落在语义变化处，不强制落在句界。
- 结构、数据、排名适合关系图、坐标、价签、流程、飞轮等；用户、员工、选择、交接适合人物、门、任务卡、气泡等。
- 这些是叙事组件类别，不是必须轮替的皮肤。视觉风格、色彩、字体和装饰全部由本期 design brief 与 token 决定。
- 同一母结构可以跨多句，但每句必须让它变形、重排或改变主体关系；静止构图换标题、卡片轮播或只有环境运动均不合格。

## 每句一个推进动作

为每句写“母结构或主体关系发生了什么推进”：汇聚、展开、跃迁、锁定、折叠、递交、注满、断裂、划掉、趋同、赢得使用等。写不出动作时回到语义设计；呼吸、旋转、淡入淡出、普通位移不能单独冒充本句主动作。一个机制可以跨多句，不要为了执行“每句有动作”而一句切一个新镜头。

## 语义设计库（方法，不是固定答案）

| 文案概念 | 可见关系 | 实现要点 |
|---|---|---|
| 发布、登场 | 分散信息聚成主体 | gather → 主体，冲击只作强调 |
| 追上、进入梯队 | 主体跨过空槽进入新关系 | hop + 保留其他梯队上下文 |
| 能力趋同 | 多条轨迹／能力向量收拢到共同前沿 | 端点汇聚、夹角缩小，不只写“趋同” |
| 生态 | 主体向外长出真实产品关系 | 辐条与节点，再整体缩成样本 |
| 成本 | 资源被消耗、价格被比较或门槛下降 | 仪表、价签、区间条，必须让“钱／成本”可见 |
| 技术位置 | 主体在坐标、梯队或雷达中的位置改变 | 轴与比较对象同时存在，不能画无意义梯形 |
| 持续使用、留存 | 用户反复选择产品，脉冲回流 | 用户与产品关系是主角，不是单独产品 Logo |
| 真实价值 | 多次使用沉淀成价值 | 用户送出的结果汇入价值环 |
| 发布日期 | 计数框变日期卡 | morphRect |
| 多项能力升级 | 同一容器依次承载不同任务 | 容器连续变形，内部内容交接 |
| 版图 | 单元铺成结构 | 芯片／卡片变形为区块 |
| 典型样本 | 整个体系缩成可观察样本 | 父组缩放，保留内部结构 |
| 转化 | 输入经过机制成为输出 | 输入管、转化器、输出表 |
| 用户持续选择 | 用户反复进入／调用 | 人物循环，产品与反馈持续在场 |
| 盲测 | 身份隐藏而任务与评价保留 | 遮眼、任务卡、匿名节点，不伪造人数 |
| 真实工作流 | 多角色在泳道中交接 | 人物动作与道具同步 |
| 用户不关心版本 | 版本标签退后，任务结果前移 | 透明度与层级变化 |
| 不愿看参数 | 人物推开参数表 | 推手动作与表飞出同步 |
| 共同迭代 | 工位重排成反馈飞轮 | 节点复用并重排 |
| 生态不等于护城河 | 循环关系与防御关系分离 | 明确 ≠，不能只换颜色 |
| 第一次／第二次使用 | 同一用户走两趟，第二次结果不同 | 路径、结果卡、回环连续 |
| 中断、人工接管 | 智能体停下，人接过同一任务 | figHand 手部跟随与 hop 交接 |
| 曝光不等于留存 | 入口增加但回流不增 | 两组数据同源对照 |
| 价格不变／更高 | 升级前后价签、区间与单位 | 不截轴，不用无关图形 |

## 承接规划表

每个镜头边界必须先写：`边界时间 | 上一镜留下的对象 | 它怎么变 | 变成下一镜的什么`。空行代表设计未完成。承接对象保持同一 DOM／场景身份，禁止闪屏或整页淡入淡出掩盖硬切。

## 分镜产物

使用 `templates/storyboard.md`，至少包含持续主体形态链、逐句分镜、承接规划表、Sprite 时间窗、数据来源与待确认事项。分镜确认仍走现有 Cheese Motion 契约，Agent 不替用户确认。
