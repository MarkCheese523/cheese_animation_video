# 数据与原图证据卡

## 数据映射声明

每个数字写代码前声明一行：

```text
// 数据:"影响约 45% 的计划扩张容量" → 20 格代表 100%，每格 5%；9 格标红 = 受影响；11 格 = 未受影响。
```

### 语义陷阱

| 原文 | 错误画法 | 正确画法 |
|---|---|---|
| 影响 45% | 条形缩到 45% | 100% 里 45% 标红 |
| 下降 30% | 柱子画成 30 | 原柱新柱并排，新柱为原柱 70% |
| 高于 | 截断坐标轴 | 从 0 起画，或只写"大数字 > 大数字" |
| 数千上万 | 编具体数字 | 保留原文措辞，大量小方块表规模 |
| 没给数字 | 编数字 | 只画相对关系，标注"示意" |

## 诚实原则

1. 只使用用户提供的数字，或能从用户原图可靠读出的数字。
2. 没有数字时只画相对关系，并明确标注“示意”。
3. 平均分、胜负数、倍数等派生指标由代码从原始数组计算，并标注“据原图计算”。
4. 不截断坐标轴。分数默认 0–100；差距很小时用大数字＋大于号，不能用截轴柱子夸大。
5. 价格区间以主体价格为 100% 画区间条，保留单位与计费口径。
6. 原图与表格冲突时先停下说明；默认以原图为准，提供一行可切换的数据源配置。

## 原图展示卡

用户给了原图，就必须先完整展示，再拆解或标记。

- `imgCard(src, aspectRatio, title, width)` 使用 `preserveAspectRatio="xMidYMid meet"`，不裁切、不变形。
- 标题写 `SOURCE · 出处说明`。
- 复杂图表至少展示约 4 秒，截图至少约 2.5 秒。
- `imgMark` 用 0–1 相对坐标圈重点，按字幕依次出现。
- 承接可从相关容器 `zoomThrough` 放大，看完后缩回下一容器，或 `emit/scatter` 拆成数据单元。
- 原图拆成数据单元时，数值仍从同一原始数组计算，不能手工另写一套导致不一致。

## 推荐图表形态

| 场景 | 形态 |
|---|---|
| 多项基准 | 小卡网格，每卡横条与数值；选中项变形成表格行 |
| 排名、梯队 | 有比较对象的梯队或坐标，主体位置连续变化 |
| 总体对比 | 平均分横条、差值括号、胜负统计 |
| 价格 | 价目表、区间条、倍数列与单位 |
| 进度、时长 | 大数字计时器 |
| 规模 | 小方块网格与原文措辞，不虚构精确数量 |
| 人数 | 简化人物网格与计数器，数量必须有来源 |

## 数据录入

```js
const BENCH = [['名称', 主体, 对手B, 对手A], /* … */]; // 注释来源与顺序
const PRICE = [['计费项', 主体, 对手下限, 对手上限, '倍数文字'], /* … */];
const average = values => values.reduce((a, b) => a + b, 0) / values.length;
```
