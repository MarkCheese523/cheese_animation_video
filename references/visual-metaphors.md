## 语义反相禁用表

> 「反相」= 画面里的图形表达的**含义与旁白说的相反**，不是画得难看。
> 这是本仓库最贵的一类返工（CASE-16）：观众看到的东西和听到的话对不上，
> 再多美术细节也救不回来。**每条都来自 `references/cases.md` 里的真实案例。**
>
> 查表顺序：先在主表里找概念 → 找到就照着画；**画完之后**再拿本表过一遍，
> 确认没有踩进语义反相。

| 错误画法 | 为什么错 | 正确画法 | 关联案例 |
|---|---|---|---|
| 拿云或机房图标当作语音源，放在人物旁边 | 画面里的图形与旁白说的相反：观众看到的是云不是人声；资产确认了来源，却没确认它在画面里代表什么 | 语音源必须是人：人物在画面里，声波弧从嘴前散开（`figAct` + `ARC`） | CASE-16 / E22 |
| 把实心字形当线稿重画成空壳描边 | 同一个标识在画面里变成了另一种图形，笔画关系被改写，识别度掉光 | 按母版原件的类型渲染：实心件保持实心，线稿件保持描边 | CASE-10 / E24 |
| 多色 Logo 压成单色后再放进画面 | 品牌标识被换成另一套配色，语义被改写成「另一个品牌」 | 保留品牌原色板，实心件与线稿件分别出图 | CASE-11 / E24 |
| 同一个母版用 pattern 点阵在两处复用 | 两处渲染出的点阵并不一致，同一个东西在画面里长成两种样子 | 需要复用的点阵用显式坐标画出，不用 pattern（`dotMatrix`） | CASE-22 / E14 |
| 上一拍的背景场景在下一拍边界没退干净 | 上一句的场景语义还留在画面里，观众读到的是两个叠加的场景 | 退场时间对齐拍次边界，背景与前景一起退 | CASE-25 / E23 |
| 同一组信号要素分散在画面两端 | 同组信息被拆成两处，读者读成两个不相干的东西 | 同组要素聚拢到一处并保持组内一致（`gather`） | CASE-17 / E18 |

## 新造画法：显式标注流程

主表查不到概念时，**允许自造**，但必须显式标注，不能默默现场发明：

1. 在本期 analysis 的两级设计卡里，把该拍标为 **本期新造**，并写清三件事：
   概念 → 画法一句话 → 为什么主表里没有这一条。
2. 该拍使用的 helper 与视觉动词仍然必须真实存在（helper 在 `templates/engine.js` /
   `templates/kit/*.js`，动词在 `references/visual-verbs.md` 的 20 个动词里）。
3. 本期结束后，把这一条回填进本表主表，并注明来源是本期新造 ——
   **没回填的自造画法，下一期还会重新发明一遍**。

标注就写在设计卡的「视觉动词」旁：`[新造] 概念 → 画法`。
自检脚本（E32）只校验本表内部的真实性与一致性；**「该拍是不是标注了新造」由语义接触表人工确认**
（见 `references/qa-delivery.md` 的人工必查项）。
