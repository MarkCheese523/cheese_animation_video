# 执行契约：竖屏解说段的固定流程与必填表格（弱模型版）

> 本契约面向**执行能力较弱的模型**。核心思路：把需要判断力的地方改写成固定流程 + 必填表格 + 查表 + 硬数字 + 自动检查。执行模型不需要审美，只要按顺序填表、查表、套引擎 helper，最后跑一遍 `?lint` 即可。
>
> 视觉方向与叙事要求（画面叙事关卡、两级设计卡）仍由 `semantic-scenes.md` / `script-storyboard.md` 管辖；本文是它们之下的**施工规范**，不替代上游判断。

## 使用方式（对人 / 对强模型）

1. 弱模型**先只输出表 A 到表 F**，不写代码。
2. 人在分镜确认闸门快速审表：每一拍的焦点是否唯一、表 E 有没有空行、坐标是否都能在布局模板里找到出处。
3. 表格确认后再让它写代码。**表格阶段改起来便宜，写进代码后修改成本高一个数量级。**

## 执行提示词（放在任务开头）

```text
你是竖屏解说动画的执行者，必须严格遵守：

1. 按顺序输出：表A 节拍表 → 表B 结构表 → 表C 布局表 → 表D 分镜表 → 表E 承接表 → 表F 元素表 → 代码。任何一张表没写完不得写代码；每张表写完对照它的"通过条件"自查一次。
2. 坐标只能从【布局模板】里抄，需要新位置时在模板坐标上做 ±整数偏移，并在注释里写明理由。安全区：x ∈ [60,1020]，元素不得进入 y ≥ 1360 的字幕区。
3. 只能调用 MotionEngine（templates/engine.js）提供的函数，禁止修改引擎、禁止自造引擎接口；缺功能写进交付说明的"待确认事项"。
4. 会变形的元素一律世界坐标 + morphRect / setBox；整体移动的刚体组用 act 的 x/y/s/r，并在注释里写"局部坐标，原点为…"。
5. 每个镜头边界都要在表E写清"谁活下来、怎么变、变成什么"。想不出来就用兜底：归档（gather/retract）到索引轨，新焦点从槽位落下（hop）。
6. 每个数字先写一行"数据→画面映射声明"，再画。
7. 写完代码在网址后加 ?lint 运行，修到面板显示"✓ 没有发现问题"再交付。
8. 禁止：整页淡入淡出、闪屏转场、display:none 切场、CSS 变量写进 SVG 属性、位置参数版 TX（一律用对象形态）、子元素开比父组更长的时间窗。
```

## 总流程：从字幕到代码的八步

```text
SRT 字幕
 │ ① 切拍:关键词出现时间           → 表A 节拍表
 │ ② 读结构:论证模式与持续主体      → 表B 结构表
 │ ③ 定布局:每拍选一个布局模板      → 表C 布局表
 │ ④ 写分镜:每拍一个焦点一个动词    → 表D 分镜表
 │ ⑤ 设承接:每个边界谁活下来        → 表E 承接表
 │ ⑥ 列元素:出生/死亡/坐标/图层     → 表F 元素表
 │ ⑦ 写代码:按引擎 helper 填入数据   → HTML
 │ ⑧ 跑检查:?lint 零报错 + 人工清单  → 交付
```

规则：每张表都有"通过条件"，不通过就回到上一步，不允许带着问题往下走。弱模型最常犯的错是从"这句话该画什么"直接跳到代码，跳过 ②⑤——结果就是 PPT。

## 表A 节拍表与节奏硬数字

**语速口径（与本仓库实测一致）**：中文旁白 280–300 字/分钟 ≈ 每字 0.20–0.21 秒；保守下限可按 3.6 字/秒估。计字：汉字 1，一个英文单词或一串数字（45%、V4.1）算 1，标点 0。

**关键词时间** = 句子开始 + (关键词前字数 ÷ 句子总字数) × 句子时长。无 SRT 时注明"按字数估算，待对轴"，不伪造毫秒。

| 项目 | 标准 |
|---|---|
| 一拍时长 | 1.5–3.5 秒 |
| 每条字幕 | 至多 1 个主拍（可附 1 个次要动作） |
| 新视觉事件间隔 | 每 2–3 秒一个；画面最多 4 秒无新变化 |
| 元素最短停留 | 文字约 1 秒；数字数据卡约 1.5 秒 |
| 入场时机 | 可比关键词提前 0.3–1 秒 |
| 强调时机 | 落在关键词时间 −0.1 ~ +0.3 秒内 |
| 仪式动作配额 | 震屏/盖章每 30 秒最多 1 次 |

字幕拆分：每屏最多 2 行、每行不超过 14 字（英文数字算半个）；长于 3.5 秒按逗号拆，拆点优先逗号、其次关键词之前。

| 拍 | 起止 | 字幕(拆分后) | 关键词@时间 | 拍类型 | 视觉动词 |
|---|---|---|---|---|---|
| 1 | | | | 引入/展开/强调/承接/停留 | 从动词表选 |

**通过条件**：字幕不超限；每拍时长在 1.5–3.5s；每拍有且只有一个视觉动词；仪式动作不超配额。

## 表B 结构表与持续主体

先识别**最外层论证模式**定整段骨架，内层模式决定每一拍画什么：

| 文案特征 | 模式 | 骨架 |
|---|---|---|
| 第一第二第三 / 三个原因 | 列举 | 索引轨 ①②③，讲到哪项哪项亮 |
| A 比 B / 而 / 相比 | 对比 | 左右两栏（L2）、天平、双柱 |
| 因为所以 / 导致 | 因果 | 链条：触发 → 作用 → 结果 |
| 从…到… / 先…再… | 流程 | 管道漏斗（L4）、行走路径 |
| 但是 / 不过 | 转折 | 翻面、划掉、天平倾斜 |
| 能否 / 什么时候 | 设问 | 问号、闸门、时钟 |
| 数字百分比排名 | 数据 | 格子阵（L8）、计数、梯队 |
| 用户投资者员工 | 人的行为 | 人物（L7）加道具 |

持续主体规则：每段只选 1 个主体对象 + 至多 1 组人物；主体必须是观众叫得出名字的（"压力①""数据中心"），禁用 P1/Block A 开发编号；主体写成**形态链**逐环对应话题（例：`压力块① → 落地 → 长成数据中心 → 被监管框罩住 → 归档回①号槽位`）；话题结束主体必须归档，不能凭空消失。

| 项目 | 内容 |
|---|---|
| 最外层模式 / 骨架 | |
| 持续主体及形态链 | |
| 人物组（角色） | |
| 上一段末帧留下的 | |
| 本段末帧留给下一段的 | |

**通过条件**：主体有观众看得懂的名字；形态链覆盖本段每个话题；首帧末帧都写清。

## 表D 分镜表与视觉动词表（映射到引擎真实 helper）

每拍先问六问：主语（=焦点）是什么？动词是什么（查下表）？有没有数字（先写映射声明）？和上一句什么关系？这拍结束后谁留下？观众此刻看哪里（只能一个答案）？

| 视觉动词 | 引擎实现 | 时长/缓动 |
|---|---|---|
| 出现、登场 | `act` s 轨道 `ps(t0)`（pop 回弹） | 0.35s back |
| 落下、归位 | `hop`（贝塞尔弧线）或 `gather` 飞向槽位 | 0.5–0.8s eio |
| 长成 | `morphRect`，**底边固定**（中心 y = 底边 − h/2） | 0.8–1.0s eio |
| 展开 | `morphRect` 小盒→大框；环→线用 `unroll` | 0.8s eio |
| 归档 | `gather`/`retract` 错开飞向目标并缩小淡出 | 每项 0.015–0.03s（大批量）/0.04–0.12s，共约 0.6s |
| 分出 | `emit`/`scatter` 从共同中心错开飞出 | 同上 back 入场 |
| 注入 | `emit` 粒子 u² 加速下落，每 0.25–0.3s 一颗 | 每颗约 0.55s |
| 堵住 | 粒子 `hop` 停在瓶颈 + 驻留函数轻微抖动 | 持续 |
| 滴出 | `emit` 少量粒子间隔约 0.5s | 每颗约 0.45s |
| 盖章 | `ps` 缩放 2.6→1 + `boot({SHAKE})` 震屏 | 0.3s back |
| 标红 | `imgMark` 或斜纹覆盖层逐项出现 | 每项 0.09s |
| 运转 | 描边/填充 opacity 按 sin(6t−0.45i) 波动 | 持续 |
| 停住 | 波动停止，opacity 固定 | 立即 |
| 划掉 | `LN` 删除线绘制 | 0.4s eo |
| 计数 | `CNT` 从 0 涨到目标 | 1–2s eo |
| 走进 | `figAct` walk 窗口 + x lin | 约 1.4s |
| 指向 | `figAct` aR 抬到 130–140 | 0.3s eo |
| 提问 | 人物 + 头顶问号 `ps` 弹出漂浮 | 0.35s back |

| 拍 | 起止 | 字幕 | 焦点 | 视觉动词 | 画面描述(一句话) | 关键词对齐 |
|---|---|---|---|---|---|---|

**通过条件**：每拍只有一个焦点；强调动作与关键词时间差在 −0.1~+0.3s；动词全部来自上表。

## 表E 承接表与决策树

```text
下一拍焦点和上一拍是同一个东西吗？
├─ 是 → 持续主体:只变形态或位置（morphRect / hop），DOM 身份不变
└─ 否 → 新焦点能从上一拍某个元素里长出来吗？
    ├─ 容器变成容器   → morphRect（同一 rect）
    ├─ 一个分出多个   → emit
    ├─ 多个汇成一个   → gather
    └─ 都不能 → 兜底:全部归档到索引轨槽位,新焦点从槽位落下(hop)。永远可用。
```

有索引轨的段落，话题切换一律走"归档 → 落下"。持续主体跨拍保持同一 DOM 身份，首帧等于上一段末帧（`snapshotState` 对照）。禁止：一句新建一页整体淡出、闪屏/色相偏移连接无关对象、新主体凭空画出。

| 边界时间 | 上一拍留下的对象 | 怎么变(手法) | 变成下一拍的什么 |
|---|---|---|---|

**通过条件**：表 E 无空行；每个边界的"怎么变"都能在上表决策树里找到路径。

## 表F 元素表

| 元素 | 是什么 | 图层 | 坐标(模板出处) | 出生时间方式 | 死亡时间方式 | 承接自 | 承接给 |
|---|---|---|---|---|---|---|---|

图层取引擎 `L.under / L.main / L.figs / L.over / L.top / L.labels`；光晕与背景放 under，人物 figs，标签 labels，HUD 类 top。

**通过条件**：坐标都有出处；无元素进 y≥1360；每个元素有出生和死亡；"承接自/承接给"至少一项非空（纯装饰除外）；子元素时间窗不长于父组（lint 检查父隐子显）。

## 数据 → 画面映射声明（必须写）

每个数字写代码前声明一行：

```text
// 数据:"影响约 45% 的计划扩张容量" → 20 格代表 100%，每格 5%；9 格标红 = 受影响；11 格 = 未受影响。
```

语义陷阱：

| 原文 | 错误画法 | 正确画法 |
|---|---|---|
| 影响 45% | 条形缩到 45% | 100% 里 45% 标红 |
| 下降 30% | 柱子画成 30 | 原柱新柱并排，新柱为原柱 70% |
| 高于 | 截断坐标轴 | 从 0 起画，或只写"大数字 > 大数字" |
| 数千上万 | 编具体数字 | 保留原文措辞，大量小方块表规模 |
| 没给数字 | 编数字 | 只画相对关系，标注"示意" |

## 动效硬数字

- 每个元素生命周期四段缺一不可：出生 → 驻留(环境运动) → 变化(形态/位置) → 退场或承接。
- 缓动：back=出生弹入/盖章；eo=到达/绘制/生长/计数；eio=位移/变形/摄像机/归档；lin=淡入淡出/走路位移/循环。
- 同一时刻最多 2 个主运动，其余只能是环境运动；任何时刻画面至少一处环境运动。
- 相邻 Sprite 时间窗交叠 0.2–0.5 秒，退场与入场在重叠区交接。
- 摄像机默认不动，只做 1.0→1.03 轻微推拉；话题切换可移 10–20px；震屏只配仪式动作（幅度 12px、0.3s，`SHAKE` 已内置）。

## 交付格式

1. 表A 至表F 全文；2. 完整代码（文件头注释含映射声明）；3. 本段末帧状态（下一段 `snapshotState` 复原用）；4. 待确认事项（估算时间、数据疑问、转写疑问）。
5. `?lint` 面板显示"✓ 没有发现问题"。

**lint 查不出、人工必查**：首帧等于上段末帧；每个边界前后 0.5s 拖动可见承接变形；每拍只有一个焦点；数字语义与映射声明一致；观众可见标签无开发编号；强调动作对准关键词。
