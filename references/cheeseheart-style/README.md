# Cheeseheart 视觉风格 · 荧光绿科技界面

## 定位

一套**可复刻的视觉皮肤**，不是一套制作流程。它规定「颜色怎么用、字怎么排、画面长什么样、动起来什么手感」，任何载体（HTML 动画、网页、PPT、封面、信息图）套上它就应该认得出来是同一个品牌。

复刻的判定标准：抽一帧出来，遮住 logo，旁人也能认出是同一条片子。

风格基线样张：`assets/reference-frame.jpg`（数据段）、`assets/reference-frame-card.jpg`（结论卡）。动手前先看这两张，比读十条规则更快对齐。

## 一屏记忆点（五条视觉 DNA）

1. **近黑底，不是纯黑**：舞台底 `#050704`（带绿的近黑）。纯黑 `#000` 会让荧光绿失去「发光」感，只在导出容器外框使用。
2. **单一主色，荧光绿 `#BCF500`**：占全部彩色面积 **80% 以上**。品牌原色是 `#A9D909`，屏幕发光提到 `#BCF500`；`#A9D909` 只用于印刷/静态物料。
3. **互补色只做点缀**：品红 `#FF4FD8`（劣势、更贵、警告）与紫 `#B48CFF`（对照模型）。合计不超过 15%，**永远不当主色**。绿↔品红是互补轴，撞色是设计意图，不是失误。
4. **中文用黑体，数字与英文用等宽**：中文 `PingFang SC`，数字/英文/单位 `JetBrains Mono`。两套字体严格分工，不混用。这一条贡献了一半的「专业感」。
5. **画面必须像「正在运行的系统」，不像「排好的版式」**：四角括角 + 顶部左右分栏 HUD + 细进度线 + 全屏扫描线 + 呼吸光晕。这层界面感是风格的骨架，抽掉就退化成普通深色幻灯片。

## 字体与字号阶梯

```css
--cjk: "PingFang SC","Microsoft YaHei","Noto Sans SC",sans-serif;
--mono: "JetBrains Mono","SF Mono",Consolas,monospace;
```

以 1080 宽舞台为基准（其他尺寸等于等比缩放，不改字号语义）：

| 层级 | 字号 | 字重 | 字体 | 说明 |
|---|---|---|---|---|
| 主视觉大字 | 58 | 900 | CJK | 片头/片尾核心词，单帧不超过 4 字 |
| 字幕 | 60–62 | 800 | CJK | 行高 1.3，最多两行 |
| 徽标/印章 | 56 | 900 | CJK | 字距 6，边框 4px |
| 数据大字 | 34–40 | 800 | MONO | 数字要跳出来时用 |
| 卡片标题 | 24–26 | 800 | CJK | — |
| 正文 | 20–28 | 700 | CJK | — |
| 等宽标签 | 22–26 | 500–600 | MONO | 字距 2–3，全大写 |
| 说明/注释 | 16–19 | 500 | MONO | 字距 0 |
| HUD | 26 | 500 | MONO | 字距 3 |

规则：
- **数字一律等宽且 `letter-spacing:0`**，否则数值跳动时宽度会抖。
- **中英混排必须在中文与英文/数字之间补一个空格**：「让 HY4 具备」「成本的 HY4 Flash」。`<b>` 包裹时把空格加在标签外侧。漏空格是最常见的廉价感来源。
- 英文标签全大写，中文标题不加标点。

## 舞台几何（1080 × 1920）

```
┌──────────────────────────────┐  y=0
│ ⌐                          ¬ │  y=36   括角 70×70，3px，只描两边
│  ● cheeseheart//…   00:12.34 │  y=80   HUD，左右各 70 边距
│  ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔  │  y=140  进度线 3px
│                              │
│        内 容 主 体 区        │  y=260–1300  可视化/卡片/图表
│                              │
│  ░░░░░░ 渐 变 遮 罩 ░░░░░░  │  y=1360 起，高 560
│       字幕第一行             │  y=1470 起，60px，居中
│       字幕第二行             │
│  ⌐                          ¬ │
└──────────────────────────────┘  y=1920
```

- 左右安全边 **50–70px**，任何文字不得越界。
- 字幕带宽 560px，渐变 `transparent → rgba(4,7,4,.85) 28% → .95`，保证字幕永远可读。
- 主体区与字幕带**不重叠**：元素要下落时，在 y=1300 之前收住或淡出。
- 括角只描两边：左上描上+左，右上描上+右，依此类推。

## 构件语法

所有构件都是「一个 g + 参数化宽高 + 一个 sprite 时间区间」，不写死单帧样式。完整代码见 `references/components.md`。

| 构件 | 形态 | 用途 |
|---|---|---|
| `chip` | 圆角矩形，主色 2–4px 描边，hero 版带 `halo` 光晕 + `glow` 滤镜 | 主体标识，会移动/变形的那一个 |
| `pill` | 全圆角标签，深绿底 + 主色描边 | 状态、型号、结论标注 |
| `card` | 圆角 14–20，底色 `rgba(8,22,8,.9)`，描边 2.5 | 内容面板，标题贴在左上 |
| `imgCard` | 白底包边 + 深绿外框 + mono 标题 | 原图/截图展示，`preserveAspectRatio="xMidYMid meet"` 不裁切 |
| `bar` | 圆角 6–8 横条，长度按百分比 | 数据对比，主色=本方，灰=基线，紫=对照 |
| `table` | 无竖线，仅底部细线，行高 130 | 多项数据对比 |
| `icon` | 48×48 线性，stroke 3，圆头圆角 | 语义图标，不用 emoji |
| `LN` | 折线，`pathLength:1` 描边生长 | 路径、因果、流程 |
| `corner` | 70×70 两边描边 | 全片常驻界面感 |
| `scan` | `repeating-linear-gradient` 2px 间隔 2px，白 2.2% | 全片常驻，制造屏幕质感 |

排版密度：**反对大卡片 + 大留白**。一屏承载 3–6 个信息块，标题 + 数据 + 结论三层齐备。空的地方用网格、光晕、括角填，不用放大字号填。

## 动效手感

| 场景 | 缓动 | 时长 |
|---|---|---|
| 元素进场（淡入上浮 18px） | `eo`（ease-out cubic） | 0.35s |
| 位移/变形 | `eio`（ease-in-out cubic） | 0.35–0.6s |
| 弹入（标签弹出） | `back`（c=1.7） | 0.25s |
| 出场 | `eo` | 0.3s |
| 镜头推近 | `eio` | 0.6–0.8s |
| 字幕单句 | 进入 0.18s 上浮 20px | — |

- **镜头只推不摇**：`scale` 在 1.0–1.15 之间，`translate` 只做垂直方向的视觉中心补偿。全片不出现旋转镜头。
- **主体位移走弧线**：两点之间用二次贝塞尔（控制点偏移 20–30%），直线位移显机械。
- **静止不超过 2 秒**：必须有元素在呼吸（光晕 `r` 波动 ±4%、扫描线移动、数字跳动）。
- **拼接用交叉淡化 0.14s**，不用闪白/闪绿/wipe 遮盖。
- **字幕与画面同步**：画面元素出现时间对齐字幕关键词，不提前超过 0.3s。

完整的曲线公式、关键帧轨道写法、节奏表见 `references/motion.md`。

## 铁律（违反即不算这个风格）

1. **禁止蓝色**（`#00e5ff`、`#3d7bff`、蓝黑底 `rgba(8,20,40)` 全部禁止）。唯一例外：用户提供的原图素材里自带的颜色。
2. **禁止纯黑大底、纯白大底**。需要高对比时用 `#050704` 与 `#DFFF9E`，不用 `#000`/`#FFF`。
3. **同屏最多三种色相**：主色 + 一个互补 + 中性灰。四色并列 = 没重点。
4. **禁止 emoji 当图标**，用线性 SVG（`icon()`）。
5. **禁止纯文字堆砌**：每屏至少一个图形机制（条形、路径、面板、图示），不能只有标题加几条要点。
6. **数值必须等宽对齐**：数字与中文量词之间留一个空格（`6 元`、`213 位`、`12 项`），与拉丁单位之间不留（`41m51s`、`100%`、`2.5x`）。
7. **不做「好看的 PPT」**：画面要能被读成「一个正在发生的动作」，不是「一页排好的信息」。

## 工作流

**Step 1 · 取骨架**
沿用主技能的 `templates/segment.html` 与 `templates/engine.js`，将本目录规范作为 skin 与构件约束。不得复制或新建第二套播放器。风格样张见 `assets/reference-frame.jpg` 与 `assets/reference-frame-card.jpg`；先对齐样张，再按本期视觉母结构设计完整跨句机制。

预览与逐帧定位沿用主技能的 `render(t)`、服务与 QA 契约。

**Step 2 · 定节奏**
先写字幕表 `SUBS = [[t0, t1, "文本"], ...]`，再排画面。画面元素的出现时间由字幕关键词反推，不要先画再对时间。

**Step 3 · 拼构件**
从 `references/components.md` 取构件，按「一个视觉机制跨多句存活」的原则组织：主体移动/变形，而不是每句换一套版式。

**Step 4 · QA（四条硬检查）**
1. **蓝色扫描**：抽帧做像素统计，蓝色主导像素应 < 0.3%（互补紫可能误判，逐帧看图确认）。
2. **对比度**：正文/小字在底色上 ≥ 7:1；主色描边在卡底上 ≥ 12:1。
3. **出界检查**：字幕、标签左右不越 50px；元素不进字幕带。
4. **接触表**：关键时间点各抽一帧拼图过目，确认无黑屏、无重影、无残字。

**Step 5 · 导出**
视频制作流程与导出链路不在本 skill 内，走 `html-animation-video`（引擎、QA、MP4 导出都在那边）。本 skill 只保证「长什么样」。

## 与其它 skill 的边界

- **`html-animation-video`**：视频制作流程、时间轴引擎、分镜方法论、MP4 导出。**做视频必须走它**，本 skill 只提供皮肤。
